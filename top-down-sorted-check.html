Plain top-down mergesort, plus a single test: after sorting both halves, merge only when A[m-1] > A[m]. A call whose whole range sits inside one run fails that test and pays nothing. This is not the run-adaptive framework — there is no run decomposition and no merge tree over runs, just the fixed dyadic recursion with some of its merges switched off. Drag the run strip at the bottom of the tree; everything above it is rebuilt on every change.

subdivision entropy HS

Top-down mergesort cuts every run along the recursion grid, so it behaves exactly as if the input had been the subdivided profile below: each run is split into the maximal recursion-tree nodes it contains. HS is the run-length entropy of that profile. Merge cost equals n·HS exactly when n is a power of two, and sits just above it otherwise.

Applying it twice changes nothing — the subdivision is its own fixed point, which is the quickest check that the equivalence is real.

charging scheme — proof of cost ≤ (H+3)n

Split every counted merge's cost at run boundaries: run i is charged its overlap with each straddling node. The green/red cut is by level: the top G = ⌊lg(2n/li)⌋ levels are green. At most 2 active nodes per level can overlap a run — one holding each endpoint; anything strictly inside straddles no boundary and the sorted check skips it. Since every subproblem on level d has size ≤ ⌈n/2d⌉ (all n, not just powers of two), the level-d charge is ≤ min{li, 2n/2d}, which sums to (G+1)li + 2n/2G ≤ li·lg(n/li) + 3li. Summing over runs gives nH + 3n. The last two columns are the two upper bounds, in the order they are applied. Hover any charged part (with charging colours on) for the level-by-level breakdown; the per-run excess average depth is in the metrics panel.

Searching compositions is exhaustive over inputs: for a fixed run-length profile the reverse-ordered construction attains the maximum cost of any array with that profile, so nothing is missed by only moving run boundaries. Push (cost − nH)/n, HS − H or the excess average depth and see whether any of them gets past 3. Ticking a conjecture turns the search into a counterexample hunt.

adversarial search

sample + climb draws structured random profiles (uniform compositions, alternating tiny/large, one-big-rest-singletons, geometric blocks), then hill-climbs from the best one by local edits — resize, rescale, split, delete, insert. climb from current skips the sampling and starts from the input in the editor.

extremify repeatedly makes the shortest runs shorter and the longest runs longer, taking the best improving polarising move each round, until nothing improves. The run count never changes; n is free to move up to the n value unless n is fixed.

anneal boundaries simulated-anneals over boundary sets with an O(log n) incremental evaluator, at a pinned n. exhaustive enumerates all 2n−1 boundary sets by a Gray-code walk, so it is a proof for that n.

Ticking a conjecture below turns any of these into a counterexample hunt: it stops the moment that conjecture fails.
